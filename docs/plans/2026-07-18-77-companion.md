# Plan: #77 discovery-polish — plugin companion sync

## Context

helixgen-core merged-pending PR
[#30](https://github.com/sheax0r/helixgen-core/pull/30) (branch
`77-discovery-polish`, helix workspace `BACKLOG.md` #77) changed
agent-facing `helixgen device` CLI surfaces. Agent-facing surfaces ship in
sync across repos, so this plugin repo needs a **companion** PR: re-sync the
authoritative `docs/CLI.md` from core's merged wording and update the two
skills whose prose describes the changed behavior (`device`, `setup`). Land
this together with core PR #30 and cross-reference both descriptions.

The core changes, and where each surfaces in this repo:

1. **Nonstandard RPC port persisted + reused as the `--port` default.**
   `device discover` records a `port` (only when nonstandard; the observed
   2001->2002 SRV+1 offset) in `~/.helixgen/devices/<serial>.json`; every
   later verb reuses it as the `--port` default (2002 otherwise). Explicit
   `--port` wins. -> `docs/CLI.md`, `device`/`setup` skills.
2. **`device discover --forget SERIAL-OR-IP [--json]`** prunes a stale
   persisted record (no network; clear error, not a traceback, on unknown
   target or no records). -> `docs/CLI.md`, `device` skill.
3. **Discover failure/report message names the effective `$HELIXGEN_HOME`
   devices dir** (was hardcoded `~/.helixgen/devices/`). Core-internal
   message wording; carried in `docs/CLI.md` sync — no bespoke skill claim.
4. **Empty/whitespace `--ip` rejected** with a clear message + nonzero exit
   (behavior change: no longer silently treated as unset). -> `docs/CLI.md`,
   `device`/`setup` skills.

Core PR #30's **live-conftest serial tie-break** (its Task 4) is **test-only
in core with no agent-facing surface** — deliberately **excluded** here.

Core touched only `docs/CLI.md` among the synced docs (**not**
`docs/helix-protocol.md` or `docs/recipe-reference.md`): the SRV-2001 /
RPC-2002 offset is already documented in `docs/helix-protocol.md`
(lines ~55–57), so those two files need no change. Verify that claim by
diffing against core before declaring them done.

Standing constraints for any plan in this repo:

- Skills operate through the `helixgen` CLI only — never patch engine
  behavior here; the engine version pin lives in the skills (`setup` step 0,
  echoed in `tone`/`device` and README).
- Never commit paid IR packs, personal device exports, or WAV audio.
- Do not bump `.claude-plugin/*.json` versions unless the plan explicitly
  cuts a release — bumping `plugin.json` + `marketplace.json` fires the
  automated release workflow when merged to `main` (`release.yml` triggers
  on those paths); never touch `stable` or `helixgen--v*` tags by hand.
  **This companion does NOT bump versions or the engine pin** — the engine
  version pin (`0.27.0`) across skills is asserted consistent by
  `test_engine_pin_is_consistent_across_surfaces`; leave it untouched. A
  plugin release (and any pin bump for a new core version) is a separate,
  later step.
- `docs/*.md` are **byte-synced from helixgen-core — core is authoritative**;
  the skill content-pin / stale-vocabulary tests exempt them
  (`tests/test_skills.py`). Sync them verbatim from core's merged tree; do
  not hand-author prose into them or add plugin-side content pins over them.
